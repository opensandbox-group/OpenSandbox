# 构建与部署

源码在仓库 [`console/`](../)（BFF + Web SPA）。与 OpenSandbox Server **同集群**部署时，Lifecycle 建议走集群内 Service。

下文命令默认在 **OpenSandbox 仓库根目录**执行。K8s 清单见 [`console/k8s/`](../k8s/README.md)。

## 前置条件

- 已部署 OpenSandbox Server（Helm `manifests/charts/opensandbox` 或等价清单），且存在 `opensandbox-server` Service。
- 已创建 ConfigMap **`opensandbox-tenants`**（`tenants.toml` 与 Server 挂载内容一致，见 [02-BFF配置与Secret.md](./02-BFF配置与Secret.md)）。
- 容器镜像仓库（示例：`YOUR_REGISTRY.example.com`，按环境替换）。

---

## 1. 构建镜像（linux/amd64）

生产节点多为 **amd64**。在 Mac ARM 上构建集群镜像时需 **`--platform linux/amd64`**，否则 Pod 可能出现 `exec format error`。

### buildx 与 Docker Hub

若 `docker pull` 成功而 `buildx build` 超时，常见原因是使用了 **`docker-container` 驱动**的独立 buildx 构建器，BuildKit 拉基础镜像时**未走**本机 `registry-mirrors`。

**推荐**：使用 **`default` 构建器**（`docker` 驱动，与本机 `docker pull` 同路径）。

```bash
export REGISTRY=YOUR_REGISTRY.example.com
export TAG=0.1.0
export PLATFORM=linux/amd64

docker buildx use default
export DOCKER_BUILDKIT=1
```

构建前登录镜像仓库：`docker login "${REGISTRY}"`。

### 基础镜像（`--build-arg`）

Dockerfile 默认使用 Docker Hub 官方 tag（`python:3.12-slim`、`node:22-alpine`、`nginx:1.27-alpine`）。  
Hub 不可达时，可将同名镜像同步到私有仓库后 **`--build-arg`** 覆盖（无需改 Dockerfile）：

```bash
export BASE=YOUR_REGISTRY.example.com/mirror
export PYTHON_IMAGE="${BASE}/python:3.12-slim"
export NODE_IMAGE="${BASE}/node:22-alpine"
export NGINX_IMAGE="${BASE}/nginx:1.27-alpine"
```

不传 `--build-arg` 时使用官方 tag。

### Mac ARM64 → 集群 amd64

- 必须 **`--platform linux/amd64`**。
- 推荐 **`docker buildx use default`**，与 `docker pull` 共用镜像加速配置。
- 跨架构构建可能较慢；生产推送常用 **`--push`** 直接推到 `${REGISTRY}`。

**BFF**

```bash
docker buildx build --platform "${PLATFORM}" \
  --build-arg PYTHON_IMAGE="${PYTHON_IMAGE:-python:3.12-slim}" \
  -t "${REGISTRY}/opensandbox-console-bff:${TAG}" \
  -f console/bff/Dockerfile \
  --push \
  console/bff
```

**Web**（先确认 [`console/web/nginx.conf`](../web/nginx.conf) 里 BFF Service 主机名与 namespace 正确）

```bash
docker buildx build --platform "${PLATFORM}" \
  --build-arg NODE_IMAGE="${NODE_IMAGE:-node:22-alpine}" \
  --build-arg NGINX_IMAGE="${NGINX_IMAGE:-nginx:1.27-alpine}" \
  -t "${REGISTRY}/opensandbox-console-web:${TAG}" \
  -f console/web/Dockerfile \
  --push \
  console/web
```

本地仅验证前端（不构建镜像）：

```bash
cd console/web && npm ci && npm run build
```

## 2. 准备 Secret 与 RBAC

```bash
kubectl apply -f console/k8s/console-bff-secret.example.yaml
kubectl apply -f console/k8s/console-bff-rbac.example.yaml
```

`opensandbox-console-bff` Secret 至少包含：

- `BFF_SESSION_SECRET` — 随机长字符串（≥32 字符）
- `BFF_ADMIN_TOKEN` — Admin 登录口令（仅 BFF，不进浏览器 bundle）

---

## 3. 部署 BFF

编辑 [`console/k8s/console-bff-deployment.example.yaml`](../k8s/console-bff-deployment.example.yaml)：

| 项 | 建议值 |
|----|--------|
| `image` | 上一步 push 的 BFF 镜像 |
| `LIFECYCLE_API_BASE` | `http://opensandbox-server.opensandbox-system.svc:8090/v1`（Service 名以 `kubectl get svc -n opensandbox-system` 为准） |
| `BFF_CORS_ORIGINS` | Web 与 BFF **同域**（推荐 nginx 反代）时可设为控制台对外 URL；跨域时必须精确匹配 SPA 源 |
| `BFF_K8S_*_DEPLOYMENT` | 与 Helm release 一致，例如 `kubectl get deploy -n opensandbox-system` 中的 controller / ingress-gateway 名称 |

```bash
kubectl apply -f console/k8s/console-bff-deployment.example.yaml
kubectl rollout status deployment/opensandbox-console-bff -n opensandbox-system
kubectl port-forward -n opensandbox-system svc/opensandbox-console-bff 8091:8091
curl -s http://127.0.0.1:8091/health
```

## 4. 部署 Web

编辑 [`console/k8s/console-web-deployment.example.yaml`](../k8s/console-web-deployment.example.yaml) 中的镜像，然后：

```bash
kubectl apply -f console/k8s/console-web-deployment.example.yaml
kubectl apply -f console/k8s/console-ingress.example.yaml
```

浏览器访问 `https://console.example.com/login`：

- **租户**：`tenants.toml` 里某租户的 API Key
- **Admin**：Secret 中的 `BFF_ADMIN_TOKEN`

## 故障排查

| 现象 | 检查 |
|------|------|
| 登录 401 | `tenants.toml` 与 Server 是否同一 ConfigMap；Key 是否有效 |
| Admin 登录失败 | Secret `BFF_ADMIN_TOKEN` 是否与输入一致 |
| `/api` 502 | Web nginx → BFF Service 名/namespace；BFF Pod 是否 Ready |
| 组件健康全 disabled | `BFF_K8S_PROBE_ENABLED`；BFF 是否 in-cluster + RBAC |
| 组件健康 `CERTIFICATE_VERIFY_FAILED` / `172.16.x.x:443` | 集群 apiserver 证书与 Pod SA `ca.crt` 不一致；优先修 CA，临时可设 `BFF_K8S_INSECURE_SKIP_TLS_VERIFY=true` 并重建 BFF 镜像/Deployment |
| 归档日志不可用 | file sink 无法被 BFF 统一读，需 OSS |
| pull 成功、build 仍 Hub timeout | 是否用了 `docker-container` buildx；改 `docker buildx use default`，或用 `--build-arg` 指定镜像仓库 |

更多 API 与功能状态：[05-功能清单.md](./05-功能清单.md)。
