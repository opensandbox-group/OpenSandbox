# 设计原则（吸取 OSEP-0006 / PR #835 教训）

## 目标

- **不改** OpenSandbox 主仓 `server/`、`specs/`、`kubernetes/` 业务代码（零 upstream 补丁为默认）。
- 研发：**租户 API Key** → 只看本 namespace 沙箱。
- 平台 Admin：**BFF 聚合** + **K8s 只读 RBAC**（P2），不用「超级 tenant Key」冒充全局。

## 不做（#835 翻版）

| 避免 | 原因 |
|------|------|
| 在 server 增加 `auth.mode=api_key_and_user`、trusted-header | 横切 authz、review 与 main 冲突成本高 |
| monorepo 内 `console/` + 全 lifecycle 审计/scope | 61 文件级 PR，易长期无法合并 |
| 浏览器长期持有 `OPEN-SANDBOX-API-KEY` | 用 BFF httpOnly session，Key 只在服务端 |
| Docker socket / runtime 专有诊断进核心 UI | 保持 runtime-neutral，用 Diagnostics API |
| 首版塞概览大盘、FSB 模板、历史 DB | 分期 P0→P2 |

## 要做

| 原则 | 做法 |
|------|------|
| 控制台解耦 | 仓库根 `console/` + 独立 Deployment（可选 Helm 子 chart） |
| 认证一条线 | 租户 Key 登录 BFF；Admin 用独立 `BFF_ADMIN_TOKEN` |
| 运行时长 | BFF 用 `createdAt` / `expiresAt` / `status` 计算 `runtimeSummary` |
| Pool | 调用现有 `/v1/pools`，UI 标明**平台级、非租户隔离** |
| 小步交付 | P0 沙箱 CRUD + 列表；P1 快照/诊断；P2 Admin 聚合与 K8s 页 |

## 分期

```text
P0  租户：登录、沙箱 list/detail/create/renew/delete/endpoint、runtimeSummary
P1  快照、diagnostics、Pool（Admin 或只读说明）
P2  Admin 跨租户 list/stats、K8s 工作负载/事件、组件健康
P3  可选：独立 PG 用量、OIDC（仍优先在 BFF 层）
```
