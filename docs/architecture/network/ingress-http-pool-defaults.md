# 保留 Ingress HTTP 连接池的既有默认行为

Ingress 对大量不同沙箱上游进行高频短 HTTP 请求时，既有空闲连接池可能因容量不足而反复重建连接。本次增加连接池配置，同时保留每个 Ingress 副本总空闲连接上限 100、每上游有效空闲连接上限 2、空闲超时 90 秒的默认行为；需要更大容量的部署显式调整配置。直接提高默认容量会增加所有部署的 socket、文件描述符和内存占用，因此不作为此次改动的默认行为。

Chart 默认使用已发布镜像，因此仅将偏离默认值的参数渲染到容器启动命令，避免旧镜像因不认识新增参数而启动失败。显式调优需要选择已支持这些参数的 Ingress 镜像。

零值沿用 Go 的既有含义：总空闲连接上限为 0 表示不设总量上限，每上游上限为 0 表示使用默认值 2，空闲超时为 0 表示不按空闲时长关闭连接。负值在启动时拒绝；Helm 必须保留用户显式配置的零值，避免二进制参数和 chart 配置产生不同解释。

配置仅作用于普通 HTTP 上游连接池，包含 SSE，且独立于连接观测开关生效。WebSocket 保留独立连接路径。验收以可重复的多上游短 HTTP 请求连接计数、响应正确性和回归测试为依据；真实集群的延迟、conntrack 与资源收益需要单独测量。
