Stable patch release on the `1.2` line, covering changes since `release-1.2.0` through both `1.2.1` release candidates and subsequent hardening. Operators and SDK users on `1.2.0` should upgrade after reviewing the compatibility notes below; server, CLI, and SDK packages publish together at `1.2.1` alongside the platform images. This draft must not be published until the Fast Sandbox configuration/runtime mismatch described below is resolved.

## Highlights

- Credential Vault Exchange delivers per-request dynamic credentials through a pluggable resolver across the server, egress, and all five SDKs, with fail-closed resolution and no vault persistence of resolved secrets ([#2457](https://github.com/opensandbox-group/OpenSandbox/pull/2457) [#2535](https://github.com/opensandbox-group/OpenSandbox/pull/2535) [#2534](https://github.com/opensandbox-group/OpenSandbox/pull/2534) [#2560](https://github.com/opensandbox-group/OpenSandbox/pull/2560)).
- Resource-aware Fast Sandbox scheduling now carries template machine shapes through creation and snapshot restore, while per-subject TCP port policies reach parity with the classic egress profile ([#2623](https://github.com/opensandbox-group/OpenSandbox/pull/2623) [#2628](https://github.com/opensandbox-group/OpenSandbox/pull/2628) [#2633](https://github.com/opensandbox-group/OpenSandbox/pull/2633) [#2662](https://github.com/opensandbox-group/OpenSandbox/pull/2662)).
- Protect sandbox data and node capacity: staged uploads preserve old content when atomic replacement is available, controller recovery keeps live-sandbox Pods safe from eviction, and Docker writable-layer disk quotas stop requested limits from being silently ignored ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478) [#2398](https://github.com/opensandbox-group/OpenSandbox/pull/2398) [#2716](https://github.com/opensandbox-group/OpenSandbox/pull/2716)).

## Server

- Resource-aware template scheduling (OSEP-0026): record each template's effective CPU/memory shape and forward it as per-sandbox limits only on `ResourceAware` pools; snapshot creation records the source limits and restore replays them, avoiding machine-shape mismatches. Pool mode is the only rollout switch, with unchanged field-omitted behavior on `LegacySlot` or older FastPath deployments ([#2602](https://github.com/opensandbox-group/OpenSandbox/pull/2602) [#2619](https://github.com/opensandbox-group/OpenSandbox/pull/2619) [#2623](https://github.com/opensandbox-group/OpenSandbox/pull/2623) [#2628](https://github.com/opensandbox-group/OpenSandbox/pull/2628) [#2633](https://github.com/opensandbox-group/OpenSandbox/pull/2633)).
- Docker sandboxes can enforce `resourceLimits.disk` as a writable-layer quota, with `storage` and `ephemeral-storage` aliases; unsupported storage drivers or invalid limits return a clear 400 instead of silently running unbounded. Bind mounts, named volumes, and read-only image layers are outside the quota, and the Windows profile keeps its existing disk-size behavior ([#2716](https://github.com/opensandbox-group/OpenSandbox/pull/2716)).
- Create Docker snapshots directly from paused sandboxes without resuming them; other runtimes retain their existing source-state requirements ([#1941](https://github.com/opensandbox-group/OpenSandbox/pull/1941)).
- Deprecate the server-proxied data path into maintenance mode: proxy routes emit `Deprecation: true`, and SDK/CLI/MCP options carry deprecation annotations or warnings. Existing traffic remains supported for security and bug fixes, but deployments should move data-plane traffic to the ingress gateway ([#2548](https://github.com/opensandbox-group/OpenSandbox/pull/2548)).
- Reject unknown fields in ten closed request objects with sanitized 422 responses instead of silently discarding them, preventing misspelled volume read-only or creation flags from being accepted without effect; aliases remain supported individually, but duplicate spellings and extra image-auth fields are rejected ([#2576](https://github.com/opensandbox-group/OpenSandbox/pull/2576)).
- Keep Kubernetes reads available under steady mutations: track informer writes per object until confirmed by WATCH instead of invalidating the entire cache after every write, avoiding unnecessary API-server traffic and 429s during renewals ([#2599](https://github.com/opensandbox-group/OpenSandbox/pull/2599)).
- Push expressible sandbox metadata equality filters into Kubernetes label selectors rather than materializing every workload, reducing list latency and memory use in large namespaces ([#2559](https://github.com/opensandbox-group/OpenSandbox/pull/2559)).
- Validate OCI template publish repositories before provisioning and require a SHA-256-pinned artifact in the expected repository before sandbox creation, preventing mutable or unrelated references from being restored ([#2491](https://github.com/opensandbox-group/OpenSandbox/pull/2491)).
- Include Pod scheduling, image-pull, and warning-event details in Kubernetes create-timeout errors before rollback deletes the workload; the lookup is bounded and best effort, and the existing 504 code and cleanup behavior remain unchanged ([#2434](https://github.com/opensandbox-group/OpenSandbox/pull/2434)).
- Restore Docker expiration timers despite concurrent container removal; other Docker restore errors now stop server startup rather than leave a healthy-looking process with expiration enforcement missing ([#2533](https://github.com/opensandbox-group/OpenSandbox/pull/2533)).
- Bound each idle-pause activity probe to one whole-exchange timeout and a 4 KiB uncompressed response, so a slow, oversized, or malformed answer skips only its own candidate instead of stalling or aborting the sweep ([#2596](https://github.com/opensandbox-group/OpenSandbox/pull/2596)).
- Reject duplicate, root, colon-containing, and server-mount-clashing Docker volume destinations before provisioning, returning 400 rather than a late Docker 500; normalized `/opt/opensandbox` overrides keep their intended behavior ([#2421](https://github.com/opensandbox-group/OpenSandbox/pull/2421) [#2505](https://github.com/opensandbox-group/OpenSandbox/pull/2505)).
- Smaller fixes: preserve declared bodies on proxied GET requests ([#2518](https://github.com/opensandbox-group/OpenSandbox/pull/2518)); report exhausted proxy connections as `503 PROXY_POOL_EXHAUSTED` ([#2519](https://github.com/opensandbox-group/OpenSandbox/pull/2519)); honor an explicit POSIX root host-path allowlist ([#2474](https://github.com/opensandbox-group/OpenSandbox/pull/2474)); allow legitimate host-path components containing `..` while still rejecting traversal components ([#2701](https://github.com/opensandbox-group/OpenSandbox/pull/2701)); keep empty template metadata-filter values ([#2461](https://github.com/opensandbox-group/OpenSandbox/pull/2461)); reject trailing newlines in gateway, bucket, and environment names ([#2499](https://github.com/opensandbox-group/OpenSandbox/pull/2499)); report invalid Kubernetes pool specs as 400 with field details ([#2702](https://github.com/opensandbox-group/OpenSandbox/pull/2702)); return specific network-policy and Fast Sandbox not-found error codes ([#2703](https://github.com/opensandbox-group/OpenSandbox/pull/2703)); reject Docker memory/disk quantities above signed int64 before contacting the daemon ([#2751](https://github.com/opensandbox-group/OpenSandbox/pull/2751)).

## SDKs

- All five SDKs accept exchange credential sources and credential-only typeless binding auth, aligned with the server and egress contract; existing inline wire payloads are preserved, but Kotlin/C# compiled consumers must recompile and review widened credential types ([#2534](https://github.com/opensandbox-group/OpenSandbox/pull/2534) [#2560](https://github.com/opensandbox-group/OpenSandbox/pull/2560)).
- Detailed download APIs expose HTTP status, headers, parsed `Content-Range`, and partial-response detection across all five SDKs, so callers can detect ignored Range requests before appending data; legacy APIs and custom adapters remain usable without implementing the optional capability ([#1597](https://github.com/opensandbox-group/OpenSandbox/pull/1597)).
- Python, JavaScript, and C# return unknown total size when content encoding prevents reliable decoded-size inference, instead of treating compressed HTTP lengths as file sizes ([#2592](https://github.com/opensandbox-group/OpenSandbox/pull/2592)).
- SDK documentation catches up with existing lifecycle/wake-retry/network options ([#2590](https://github.com/opensandbox-group/OpenSandbox/pull/2590)), exchange credentials and template workflows in Python/JavaScript/Go ([#2597](https://github.com/opensandbox-group/OpenSandbox/pull/2597)), Kotlin template build/poll support ([#2620](https://github.com/opensandbox-group/OpenSandbox/pull/2620)), and explicit native format in S3 examples ([#2506](https://github.com/opensandbox-group/OpenSandbox/pull/2506)).

### Python

- MCP adds `command_get_status` and `command_get_logs` for background-command state, exit codes, and incremental output, with opaque cursors for polling ([#2648](https://github.com/opensandbox-group/OpenSandbox/pull/2648)).
- Silent command SSE connections now fail with `SandboxTimeoutException` after `max(request_timeout, 30s)` without bytes, instead of hanging indefinitely; healthy pings reset the idle-read timer ([#2527](https://github.com/opensandbox-group/OpenSandbox/pull/2527)).
- Graceful async pool shutdown drains scheduled cleanup kills within its shared budget instead of immediately cancelling them and leaving untracked sandboxes until TTL ([#2507](https://github.com/opensandbox-group/OpenSandbox/pull/2507)).
- Release abandoned sync downloads, unread legacy async streams, and responses whose metadata mapping fails, preventing connection-pool exhaustion; oversized range integers become unknown metadata ([#2487](https://github.com/opensandbox-group/OpenSandbox/pull/2487) [#2531](https://github.com/opensandbox-group/OpenSandbox/pull/2531) [#2570](https://github.com/opensandbox-group/OpenSandbox/pull/2570)).

- Smaller fixes: scope endpoint invalidation to the relevant in-flight key ([#2409](https://github.com/opensandbox-group/OpenSandbox/pull/2409)); honor redirect options and event hooks in network-policy/vault adapters ([#2553](https://github.com/opensandbox-group/OpenSandbox/pull/2553)); expose actionable SDK errors to MCP clients ([#2524](https://github.com/opensandbox-group/OpenSandbox/pull/2524)).

- Smaller fixes: unbounded redirect settings no longer trigger immediate Node.js request timeouts ([#2488](https://github.com/opensandbox-group/OpenSandbox/pull/2488)); isolated-session failures expose structured `SandboxApiException` fields ([#2466](https://github.com/opensandbox-group/OpenSandbox/pull/2466)); closing a detailed download inside its own iteration loop ends cleanly instead of raising `TypeError` ([#2514](https://github.com/opensandbox-group/OpenSandbox/pull/2514)).

## Controller

- Scope informer caches with optional `--namespaces` / `controller.namespaces` to reduce startup memory use on large shared clusters; the empty default remains cluster-wide ([#2571](https://github.com/opensandbox-group/OpenSandbox/pull/2571)).

- Pass additional ordinary-controller flags through `controller.extraArgs` in the controller chart ([#2566](https://github.com/opensandbox-group/OpenSandbox/pull/2566)).

- Stage ordinary uploads and isolated-session uploads/replacements before rename, preserving previous content if staging fails. Atomic replacement requires a writable containing directory: existing writable files retain a non-atomic in-place fallback on staging permission errors, with further metadata/inode caveats below ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- Preserve lower-layer contents, symlinks, and executable/special modes during isolated-workspace copy-up and directory rename, while rejecting symlink chmod rather than following host targets ([#2638](https://github.com/opensandbox-group/OpenSandbox/pull/2638)).
- Honor kernel whiteouts, opaque directories, and deleted ancestors in isolated-file reads/listings so deleted lower-layer content no longer reappears ([#2469](https://github.com/opensandbox-group/OpenSandbox/pull/2469)).
- Stabilize initial MITM CA selection and refresh trust stores after Kubernetes egress-sidecar certificate rotation, avoiding persistent TLS failures after sidecar restarts ([#2582](https://github.com/opensandbox-group/OpenSandbox/pull/2582)).
- Keep foreground isolated code off the persistent shell's stdin so `read`/`cat` cannot consume execution markers or corrupt later runs; syntax errors end the run with status 2 while preserving the session ([#2517](https://github.com/opensandbox-group/OpenSandbox/pull/2517)).
- Deleting an ordinary Bash session now terminates every active run's process group, including overlapping runs and processes registering during deletion, rather than leaving earlier runs alive ([#2731](https://github.com/opensandbox-group/OpenSandbox/pull/2731)).
- Closing a PTY now hangs up its shell before killing the shell's process group, allowing ordinary background jobs in separate job-control groups to exit instead of surviving session deletion; jobs that ignore SIGHUP retain terminal-like survival semantics ([#2733](https://github.com/opensandbox-group/OpenSandbox/pull/2733)).
- Restore sustained Jupyter startup retries and clean up unsuccessful sessions; unsupported languages now fail promptly when the kernel list confirms no matching kernel ([#2486](https://github.com/opensandbox-group/OpenSandbox/pull/2486) [#2689](https://github.com/opensandbox-group/OpenSandbox/pull/2689)).
- Emit Jupyter completion only after the matching reply and idle state, with output delivered first and kernel errors retained instead of racing into success ([#2606](https://github.com/opensandbox-group/OpenSandbox/pull/2606)).
- Retry SQL setup on a later execution after connection/initialization failure and close unsuccessful connection pools, so a temporary database outage no longer permanently disables SQL execution ([#2757](https://github.com/opensandbox-group/OpenSandbox/pull/2757)).
- **Security hardening:** percent-encode control characters and DEL in download filenames instead of inserting them raw into `Content-Disposition` ([#2741](https://github.com/opensandbox-group/OpenSandbox/pull/2741)).
- Smaller fixes: flush pending PTY output before the holder's exit frame ([#2644](https://github.com/opensandbox-group/OpenSandbox/pull/2644)); encode extended filenames with RFC 8187 rules ([#2516](https://github.com/opensandbox-group/OpenSandbox/pull/2516)); reject directory downloads and explain malformed ranges ([#2451](https://github.com/opensandbox-group/OpenSandbox/pull/2451)); use Linux inode birth timestamps when available ([#2604](https://github.com/opensandbox-group/OpenSandbox/pull/2604)); resolve cgroup-v1 metrics/OOM paths relative to mount roots ([#2641](https://github.com/opensandbox-group/OpenSandbox/pull/2641)); render SQL byte-valued columns as strings ([#2685](https://github.com/opensandbox-group/OpenSandbox/pull/2685)); return 404 for unknown command logs and validate cursors ([#2686](https://github.com/opensandbox-group/OpenSandbox/pull/2686)); reject invalid search globs consistently ([#2687](https://github.com/opensandbox-group/OpenSandbox/pull/2687)); preserve literal escapes in single-quoted exported environment values ([#2772](https://github.com/opensandbox-group/OpenSandbox/pull/2772)).

## Networking

### egress

- Credential Vault Exchange (OSEP-0025) resolves fresh headers per matched request through a Unix-socket or HTTPS resolver, using egress-derived sandbox identity and the complete request target. Existing sidecar and Fast Sandbox paths fail closed on resolution errors, and resolved material is neither persisted nor cached by the vault ([#2457](https://github.com/opensandbox-group/OpenSandbox/pull/2457) [#2495](https://github.com/opensandbox-group/OpenSandbox/pull/2495) [#2500](https://github.com/opensandbox-group/OpenSandbox/pull/2500) [#2501](https://github.com/opensandbox-group/OpenSandbox/pull/2501) [#2535](https://github.com/opensandbox-group/OpenSandbox/pull/2535) [#2538](https://github.com/opensandbox-group/OpenSandbox/pull/2538) [#2539](https://github.com/opensandbox-group/OpenSandbox/pull/2539) [#2547](https://github.com/opensandbox-group/OpenSandbox/pull/2547) [#2549](https://github.com/opensandbox-group/OpenSandbox/pull/2549) [#2563](https://github.com/opensandbox-group/OpenSandbox/pull/2563)).
- Fast Sandbox now accepts and enforces port-only and IP/CIDR-plus-port TCP policies per subject, including original-destination checks through MITM, with the same deny precedence as the classic profile ([#2662](https://github.com/opensandbox-group/OpenSandbox/pull/2662)).
- Opt in to blocking established traffic when tightening a dns+nft sidecar policy with `PATCH` or `DELETE /policy?dropEstablished=true`, rather than leaving keep-alive connections exempt; this installs packet drops, not TCP resets or conntrack deletion, and does not support Fast Sandbox ([#2346](https://github.com/opensandbox-group/OpenSandbox/pull/2346)).
- **[EXPERIMENTAL]** Strict Fast Sandbox management adds protected Vault v2 persistence, durable owner-retirement fences, and conditional server mutations that distinguish deleted-and-recreated vaults despite revision reuse; defaults remain v1, and enabling strict mode requires a matching manager and its deployment contract ([#2441](https://github.com/opensandbox-group/OpenSandbox/pull/2441) [#2460](https://github.com/opensandbox-group/OpenSandbox/pull/2460) [#2493](https://github.com/opensandbox-group/OpenSandbox/pull/2493)).

- Fast Sandbox DNS leases now renew their actual kernel expiry, and removing one subject preserves other subjects' unexpired leases, avoiding connection failures to cached addresses ([#2652](https://github.com/opensandbox-group/OpenSandbox/pull/2652) [#2653](https://github.com/opensandbox-group/OpenSandbox/pull/2653)).

## Fast Sandbox

- **Release blocker:** the default Fast Sandbox chart now includes `runtimeEnvironments` → `firecracker.firecracker.vmmDir`, but the pinned runtime has no such field and rejects unknown configuration keys. ## Upgrade & Compatibility

- **Release blocker:** the default Fast Sandbox chart now includes `runtimeEnvironments` → `firecracker.firecracker.vmmDir`, but the pinned runtime has no such field and rejects unknown configuration keys. Before publishing, advance to a verified compatible upstream version with matching images or withhold that configuration addition; managed VMM selection must not be advertised as available with the current pin ([#2795](https://github.com/opensandbox-group/OpenSandbox/pull/2795) [fast-sandbox#189](https://github.com/opensandbox-group/fast-sandbox/pull/189)).
- Breaking request validation: unknown keys in image/auth/platform/volume/host/PVC/OSSFS/credential-proxy/snapshot-create/renew objects now return 422; correct or remove them, and send either the alias or snake_case spelling, not both. Remove TypeScript `ImageAuth.token` and Docker-config extras; registry tokens belong in `password` alongside `username` ([#2576](https://github.com/opensandbox-group/OpenSandbox/pull/2576)).
- Deprecation: `/sandboxes/{id}/proxy/{port}`, `use_server_proxy`, and the matching SDK/CLI/MCP options are maintenance-only, not removed; expose sandbox traffic through the ingress gateway and migrate away from the proxy option ([#2548](https://github.com/opensandbox-group/OpenSandbox/pull/2548)).
- Docker disk quotas: a supplied `resourceLimits.disk` (or alias) is no longer ignored; it must be positive and supported by the daemon's storage driver, such as overlay2 on XFS with project quotas, or creation returns 400. The quota covers only the writable container layer; configure mounted-volume capacity separately ([#2716](https://github.com/opensandbox-group/OpenSandbox/pull/2716)).
- Docker startup: expiration-restore errors other than concurrent container removal now prevent startup; run the server under a restarting supervisor and investigate persistent daemon errors ([#2533](https://github.com/opensandbox-group/OpenSandbox/pull/2533)).
- Docker mounts: duplicate, root, colon-containing, or server-reserved destinations now fail early with `400 VOLUME::INVALID_MOUNT_PATH`; use distinct valid paths rather than relying on the former late Docker failure ([#2421](https://github.com/opensandbox-group/OpenSandbox/pull/2421) [#2505](https://github.com/opensandbox-group/OpenSandbox/pull/2505)).
- Host-path allowlists: an explicitly configured `/` now authorizes all POSIX descendants as intended; use narrower prefixes where full-root access is not intended ([#2474](https://github.com/opensandbox-group/OpenSandbox/pull/2474)).
- OCI templates: publish targets must be valid repositories and successful artifacts must carry a full SHA-256 digest in that repository; rebuild templates whose references are mutable, malformed, or unrelated ([#2491](https://github.com/opensandbox-group/OpenSandbox/pull/2491)).
- Fast Sandbox resource accounting: template CPU/memory shapes take effect on `ResourceAware` pools, and new snapshots replay recorded source limits; restore-time caller limits must match that recorded shape. Roll out with ResourceAware pools rather than a server flag; legacy pools and snapshots without recorded limits retain their prior behavior ([#2623](https://github.com/opensandbox-group/OpenSandbox/pull/2623) [#2628](https://github.com/opensandbox-group/OpenSandbox/pull/2628) [#2633](https://github.com/opensandbox-group/OpenSandbox/pull/2633)).
- Idle-pause probes: return uncompressed JSON no larger than 4 KiB and complete within `timeoutSeconds` for the entire exchange; violations produce an error verdict and skip that candidate ([#2596](https://github.com/opensandbox-group/OpenSandbox/pull/2596)).
- Template filtering: `metadata=env=` now selects the empty value rather than dropping the filter ([#2461](https://github.com/opensandbox-group/OpenSandbox/pull/2461)).
- Validation: remove trailing whitespace/newlines from gateway addresses, bucket names, and template environment-variable names; the previously accepted trailing-newline cases are rejected ([#2499](https://github.com/opensandbox-group/OpenSandbox/pull/2499)).
- Error handling: proxy pool exhaustion now returns `503 PROXY_POOL_EXHAUSTED` rather than generic 500, without changing the pool wait timeout ([#2519](https://github.com/opensandbox-group/OpenSandbox/pull/2519)).
- Error handling: invalid Kubernetes pool specs now return `400 SANDBOX::INVALID_PARAMETER` with Kubernetes validation details rather than 500 ([#2702](https://github.com/opensandbox-group/OpenSandbox/pull/2702)).
- Error handling: invalid network-policy actions/scopes use `SANDBOX::INVALID_PARAMETER`, and unavailable Fast Sandbox routes use `FSB::SANDBOX_NOT_FOUND`; update clients matching the former `GENERAL::UNKNOWN_ERROR` code ([#2703](https://github.com/opensandbox-group/OpenSandbox/pull/2703)).
- Docker resource validation: memory and disk quantities above signed int64 now fail before daemon calls; use representable quantities ([#2751](https://github.com/opensandbox-group/OpenSandbox/pull/2751)).
- CLI: explicitly zero/negative request timeouts are usage errors rather than falling back to 30 seconds; choose a positive timeout ([#2742](https://github.com/opensandbox-group/OpenSandbox/pull/2742)).
- CLI: empty `--rule` targets now exit 2 as usage errors rather than 1 from model validation; scripts matching exit codes should account for this ([#2692](https://github.com/opensandbox-group/OpenSandbox/pull/2692)).
- CLI config initialization now exits 1, not 0, when the destination exists, without modifying it; scripts should handle refusal explicitly and use `--force` only for intended overwrites ([#2743](https://github.com/opensandbox-group/OpenSandbox/pull/2743)).
- Node-agent VM console collection is opt-in: include `vm-console` in sources, align `hostPaths.vmConsole` with the Fast Sandbox runtime state root, and ensure the DaemonSet covers every runtime node. Collection requires the new VM metadata contract; VM console output families in the file sink do not expire automatically ([#2234](https://github.com/opensandbox-group/OpenSandbox/pull/2234) [#2677](https://github.com/opensandbox-group/OpenSandbox/pull/2677)).
- Google ADK example: use ADK 2.13.0's native environment/toolset instead of the removed handwritten tools; prompts share a workspace until toolset close, and the example uses a single LiteLLM model configuration ([#2734](https://github.com/opensandbox-group/OpenSandbox/pull/2734)).
- Contributor policy: new code contributions require DCO sign-offs (`git commit -s`), documentation contributions follow CC-BY-4.0, and formal asynchronous TSC decisions require a majority of voting members; runtime licensing and APIs are unchanged ([#2490](https://github.com/opensandbox-group/OpenSandbox/pull/2490)).
- Artifact verification: current umbrella workflows do not supply the blanket signing/provenance coverage previously implied by the docs; BOM digest matching alone is not proof of origin, and unmet signature requirements must not be bypassed ([#2467](https://github.com/opensandbox-group/OpenSandbox/pull/2467)).
- Kotlin/C# credential models are not ABI-compatible with 1.2.0: recompile, handle the widened `CredentialSource` variant, and review inline-only getter assignments and nullable/typeless authentication assumptions. Existing inline construction is supported, but blanket source compatibility is not guaranteed ([#2560](https://github.com/opensandbox-group/OpenSandbox/pull/2560)).
- Exchange auth carries only `credential`, not `type: null` or static-auth fields; Python inline sources now reject extra keys. Generated Python variants become flat `CredentialAuth`/`CredentialSource` models, so prefer handwritten models; Go source/metadata additions can break positional literals, which should become keyed literals ([#2534](https://github.com/opensandbox-group/OpenSandbox/pull/2534)).
- Detailed downloads are optional capabilities: existing adapters need no changes unless offering them. Python/Go expose separate download interfaces, JavaScript methods are optional, C# requires `IDownloadSandboxFiles` for its extensions, and Kotlin defaults report unsupported operations ([#1597](https://github.com/opensandbox-group/OpenSandbox/pull/1597)).
- Before appending a resumed download, check 206/`isPartial` and the range metadata; a 200 response means Range was ignored. Unknown totals use `-1`, malformed ranges retain raw headers, line-limited reads do not prove full file size, and detailed bodies must be explicitly closed; Python parsed range integers are bounded to signed int64 ([#1597](https://github.com/opensandbox-group/OpenSandbox/pull/1597) [#2570](https://github.com/opensandbox-group/OpenSandbox/pull/2570)).
- Encoded downloads in Python/JavaScript/C# can now report total size `-1`, including when encoding headers are not sufficiently visible; HTTP length/range headers may describe encoded bytes, not decoded output. Do not derive decoded progress or resume offsets from them; Kotlin/Go are outside this fix ([#2592](https://github.com/opensandbox-group/OpenSandbox/pull/2592)).
- Python download errors now use SDK exception subclasses during setup and iteration; catch those instead of raw `httpx` exceptions and inspect `__cause__` for the original error. Cancellation behavior is unchanged ([#2515](https://github.com/opensandbox-group/OpenSandbox/pull/2515) [#2525](https://github.com/opensandbox-group/OpenSandbox/pull/2525)).
- Python SSE timeout is an idle-read limit, not a command deadline: increase `request_timeout` for legitimate longer silence, while bytes/pings reset the timer and expiry does not resend the command ([#2527](https://github.com/opensandbox-group/OpenSandbox/pull/2527)).
- Python graceful pool shutdown shares one `drain_timeout` between in-flight work and cleanup kills, so shutdown can wait longer; non-graceful shutdown and budget expiry still cancel remaining work ([#2507](https://github.com/opensandbox-group/OpenSandbox/pull/2507)).
- Python network-policy/vault adapters now honor explicit redirect settings and hooks; default redirect behavior and protected-header stripping remain unchanged ([#2553](https://github.com/opensandbox-group/OpenSandbox/pull/2553)).
- MCP background polling should read logs once more after status becomes non-running; empty output is not completion. Reuse opaque cursors and retain the prior cursor when none is returned; omitting a cursor can return the full background log without a size cap ([#2648](https://github.com/opensandbox-group/OpenSandbox/pull/2648)).
- JavaScript command timeouts keep nearest-millisecond rounding with a positive minimum of 1 ms; negative, non-finite, and overflowing command values fail locally, while zero/omitted semantics are unchanged ([#2440](https://github.com/opensandbox-group/OpenSandbox/pull/2440)).
- Kotlin timeout ceiling applies to all fractional milliseconds, not only sub-millisecond values: 500 microseconds becomes 1 ms and 1.5 ms becomes 2 ms; zero and invalid-duration handling remain unchanged ([#2537](https://github.com/opensandbox-group/OpenSandbox/pull/2537)).
- JavaScript redirect deadlines are armed only for finite positive values; zero, negative, and infinite values disable them, unlike command-timeout validation. Match isolated-session failures by structured status/request/error fields rather than the old message text ([#2488](https://github.com/opensandbox-group/OpenSandbox/pull/2488) [#2466](https://github.com/opensandbox-group/OpenSandbox/pull/2466)).
- Go `Execution.Text()` now concatenates code fragments faithfully; use keyed `Execution` literals because the private formatting field changes construction and equality. Struct copies retain formatting mode but JSON reconstruction does not; after deserialization, concatenate stdout text explicitly when exact code-output reconstruction is required ([#2447](https://github.com/opensandbox-group/OpenSandbox/pull/2447)).
- Go generic retry delay is `max(backoff, min(Retry-After, 60s))`; configured backoff above 60 seconds remains intact, overflow saturates, and retry eligibility/defaults are unchanged ([#2452](https://github.com/opensandbox-group/OpenSandbox/pull/2452) [#2508](https://github.com/opensandbox-group/OpenSandbox/pull/2508) [#2509](https://github.com/opensandbox-group/OpenSandbox/pull/2509)).
- Go wake enforcement starts after a marked response, measures elapsed budget from loop start, and bounds final headers including redirects, not established bodies. In-flight expiry matches `context.DeadlineExceeded`, not `SandboxWakeTimeoutError`, and must not be assumed safely replayable; generic waits that cannot fit return the latest ordinary error, while earlier caller deadlines still win ([#2572](https://github.com/opensandbox-group/OpenSandbox/pull/2572) [#2611](https://github.com/opensandbox-group/OpenSandbox/pull/2611)).
- Go Running and interpreter readiness remain separate phases rather than one global create deadline; Running expiry consistently yields `SandboxRunningTimeoutError`, interpreter-budget expiry yields `SandboxReadyTimeoutError`, and interpreter caller-deadline identity is retained. Legacy successful completion without `exit_code` still infers zero ([#2528](https://github.com/opensandbox-group/OpenSandbox/pull/2528) [#2668](https://github.com/opensandbox-group/OpenSandbox/pull/2668) [#2480](https://github.com/opensandbox-group/OpenSandbox/pull/2480) [#2504](https://github.com/opensandbox-group/OpenSandbox/pull/2504)).
- Go pool shutdown waiters can cancel without cancelling the primary cleanup; primary drain cancellation completes STOPPED before returning the context error, and independent acquires are not cancelled. Cancelled acquire errors wrap the context error in `PoolAcquireFailedError` ([#2542](https://github.com/opensandbox-group/OpenSandbox/pull/2542) [#2617](https://github.com/opensandbox-group/OpenSandbox/pull/2617) [#2616](https://github.com/opensandbox-group/OpenSandbox/pull/2616)).
- Go pool destruction defaults to a 30-second drain, with explicit zero remaining unbounded; `PoolDestroyIncompleteError` leaves DESTROYING fenced for retry. Custom state stores must honor context cancellation ([#2580](https://github.com/opensandbox-group/OpenSandbox/pull/2580)).
- Upload atomicity: ordinary uploads and isolated uploads/replacements stage content when directory permissions permit; an existing writable file falls back to in-place truncation if staging creation gets a permission error, so failed writes are not unconditionally safe. Use writable containing directories when atomic replacement is required; ordinary `/files/replace` remains in-place, and atomicity is per content write, not an entire batch or subsequent metadata updates ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- Upload metadata: staged replacements preserve modes, including special bits, but not xattrs, ACLs, capabilities, or existing SELinux labels; reapply required metadata. Ordinary ownership preservation is best effort, while isolated writes use the session UID/GID and can fail if that ownership cannot be applied ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- Upload inode/storage semantics: hardlinks and open readers retain the old inode; multipart overwrites may temporarily need the old file, staged copy, and multipart spool, approximately three times the content size. Killed writers can leave staging files, directory sync is best effort rather than unconditional power-loss durability, and safe cleanup may be needed ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- Upload destinations: devices/FIFOs are rejected, bind-mounted file targets can fail with `EBUSY`, sticky-directory rules can reject rename, and Windows open-file/concurrent replacement can fail. Workspace symlink destinations stay rejected; permitted bind/confined-view symlink write-through is retained ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- Reserved staging names: avoid `.osb-upload-` and `.osb-staging-` names, particularly either prefix followed by exactly 16 hexadecimal characters; matching entries are filtered or rejected by relevant APIs. Rename pre-existing collisions through direct filesystem access; these filters are not an additional isolation boundary ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- Isolated copy-up: renamed lower entries receive session ownership while retaining modes; deleted sources now fail instead of resurrecting. Workspace symlink chmod is rejected, so chmod the permitted target explicitly; lower-only destination directories still merge on rename rather than providing full POSIX rename parity ([#2638](https://github.com/opensandbox-group/OpenSandbox/pull/2638)).
- Isolated overlay reads now hide whiteouts and opaque/deleted ancestors, and unreadable upper files retain their error rather than exposing lower content; API `.wh.` markers are still not interpreted by the running kernel overlay ([#2469](https://github.com/opensandbox-group/OpenSandbox/pull/2469)).
- Isolated foreground runs now read `/dev/null`, matching background runs; provide input through files or here-documents. Scripts transfer completely before execution, and syntax errors return status 2 without destroying the session ([#2517](https://github.com/opensandbox-group/OpenSandbox/pull/2517)).
- Deleting an ordinary Bash session terminates all overlapping active runs, not only the latest run; callers must not use session deletion while expecting earlier runs to survive ([#2731](https://github.com/opensandbox-group/OpenSandbox/pull/2731)).
- Single-quoted exported values keep literal backslash escapes across runs instead of decoding them accidentally; remove workarounds that depended on the former decoding ([#2772](https://github.com/opensandbox-group/OpenSandbox/pull/2772)).
- Directory downloads now return `400 INVALID_REQUEST_BODY`; use `directories/list`. Malformed ranges retain 416 but gain an explanatory message; valid ranges beyond EOF retain their existing response ([#2451](https://github.com/opensandbox-group/OpenSandbox/pull/2451)).
- Download filenames use RFC 8187 percent encoding, including punctuation and control bytes; parse `filename*` accordingly rather than treating its encoded header value as the literal filename ([#2516](https://github.com/opensandbox-group/OpenSandbox/pull/2516) [#2741](https://github.com/opensandbox-group/OpenSandbox/pull/2741)).
- Creation timestamps in ordinary Linux file info/search/list use inode birth time when supported, falling back to ctime/mtime otherwise; isolated metadata and other platforms are unchanged. Atomic replacement creates a new inode and can therefore change creation time ([#2604](https://github.com/opensandbox-group/OpenSandbox/pull/2604)).
- Command logs now return 404 for unknown IDs and 400 for malformed, negative, or overflowing cursors instead of silently restarting at zero ([#2686](https://github.com/opensandbox-group/OpenSandbox/pull/2686)).
- Invalid ordinary file-search globs now return `400 INVALID_REQUEST`, including against empty directories; validate the pattern instead of retrying ([#2687](https://github.com/opensandbox-group/OpenSandbox/pull/2687)).
- Jupyter authentication: explicit `JUPYTER_TOKEN` wins; otherwise custom images must provide discoverable matching-port runtime files with accepted ownership/permissions, or configuration fails immediately. Startup retry delays again span approximately five minutes, but this is not a total wall-clock deadline because REST calls have their own timeout ([#2448](https://github.com/opensandbox-group/OpenSandbox/pull/2448) [#2486](https://github.com/opensandbox-group/OpenSandbox/pull/2486)).
- Unsupported Jupyter languages fail promptly once a nonempty kernelspec list proves no match; `/code/context` returns 400, while `/code` retains its existing error mapping. Install the needed kernel rather than relying on retries ([#2689](https://github.com/opensandbox-group/OpenSandbox/pull/2689)).
- Jupyter success events now follow the matching execution reply and idle status after output; failures end in an error event rather than a success-completion event ([#2606](https://github.com/opensandbox-group/OpenSandbox/pull/2606)).
- Legacy SSE compatibility is off by default and removes `exit_code` from both successful and error events, losing structured failure codes; prefer upgrading affected Kotlin/JVM deployments to shaded `sandbox-api` 1.0.18+ rather than enabling the workaround ([#2472](https://github.com/opensandbox-group/OpenSandbox/pull/2472)).
- PTY exit can wait up to two seconds for background descendants holding output open so the holder's final output is not lost ([#2644](https://github.com/opensandbox-group/OpenSandbox/pull/2644)).
- Explicit PTY close sends SIGHUP and allows up to 500 ms for shell exit before the existing group kill; normal shell jobs now terminate, while `nohup` or HUP-ignoring jobs can survive. Pipe mode is unchanged, and close can take up to 500 ms longer ([#2733](https://github.com/opensandbox-group/OpenSandbox/pull/2733)).
- SQL byte-valued columns now render as strings rather than decimal byte arrays, with NULL unchanged; failed setup is retried by a later execution, not by automatically replaying queries ([#2685](https://github.com/opensandbox-group/OpenSandbox/pull/2685) [#2757](https://github.com/opensandbox-group/OpenSandbox/pull/2757)).
- Cgroup-v1 metrics and OOM paths now honor mount roots, so affected deployments report sandbox limits instead of host capacity; review dashboards, while cgroup-v2 behavior is unchanged ([#2641](https://github.com/opensandbox-group/OpenSandbox/pull/2641)).
- MITM trust refresh covers Kubernetes sidecar CA rotation, not pinned-CA Fast Sandbox pools; applications that cache trust in memory may still require restart after rotation ([#2582](https://github.com/opensandbox-group/OpenSandbox/pull/2582)).
- Command log consumers must tolerate the additive `command_id` field; sampling is unchanged, so these operational logs are not a complete audit trail ([#2598](https://github.com/opensandbox-group/OpenSandbox/pull/2598)).
- Controller namespace scoping must include every managed workload namespace; empty/separator-only values remain cluster-wide. RBAC is unchanged and cache scoping is not a tenant-security boundary; ConfigMap watchers continue using `POD_NAMESPACE` ([#2571](https://github.com/opensandbox-group/OpenSandbox/pull/2571)).
- Lowering `poolMax` now removes idle excess based on total pool size; allocated Pods can keep the pool above the maximum until released ([#2470](https://github.com/opensandbox-group/OpenSandbox/pull/2470)).
- Rootfs snapshots without required commit digests now fail with `CommitResultUnavailable` / `CommitResultIncomplete` and `PauseFailed`, retaining Pods so pause can be retried. Previously successful or legacy snapshots are not retroactively repaired ([#2482](https://github.com/opensandbox-group/OpenSandbox/pull/2482)).
- Controller election timings default to lease/renew/retry of 15s/10s/2s; custom values must satisfy lease > renew > 1.2×retry, and longer leases delay takeover. Set them through the three `--leader-elect-*` flags or `controller.leaderElection` values ([#2651](https://github.com/opensandbox-group/OpenSandbox/pull/2651)).
- Review `controller.podRecovery.*` before upgrading: settings previously ignored due to the ConfigMap namespace error now take effect. Helm relocates the managed ConfigMap, while plain rendered-manifest application can leave an obsolete copy in the old namespace ([#2694](https://github.com/opensandbox-group/OpenSandbox/pull/2694)).
- Exchange credentials are opt-in and require aligned server/SDK/egress versions; typeless `auth: {"credential":"name"}` applies to exchange sources, while static auth/substitutions retain their inline-source constraints. The sidecar live revision runtime does not support exchange, and compatibility with future Fast Sandbox credential-bound request admission is not established ([#2501](https://github.com/opensandbox-group/OpenSandbox/pull/2501) [#2549](https://github.com/opensandbox-group/OpenSandbox/pull/2549)).
- Resolver isolation remains mandatory: caller authentication is not implemented, and the Ed25519/JWKS proposal is design-only. Use a protected UDS or an HTTPS endpoint reachable only by trusted egress processes; never expose resolver destinations through sandbox allow rules, and do not treat the sidecar MITM UID exclusion as sufficient isolation by itself ([#2549](https://github.com/opensandbox-group/OpenSandbox/pull/2549) [#2563](https://github.com/opensandbox-group/OpenSandbox/pull/2563) [#2631](https://github.com/opensandbox-group/OpenSandbox/pull/2631)).
- Resolver failures return buffered 407 responses or terminate streams rather than forwarding without credentials; timeout defaults to 2 seconds and concurrency to 32. Use valid resolver timeout/concurrency settings and install private resolver CAs in the trust store rather than copying the smoke harness's process-wide CA override ([#2500](https://github.com/opensandbox-group/OpenSandbox/pull/2500) [#2535](https://github.com/opensandbox-group/OpenSandbox/pull/2535) [#2538](https://github.com/opensandbox-group/OpenSandbox/pull/2538) [#2547](https://github.com/opensandbox-group/OpenSandbox/pull/2547)).
- Strict management remains a separate default-off choice: enable `OPENSANDBOX_EGRESS_ACTIONS_API_VERSION=sandbox.fast.io/actions/v2` only with matching Fastlet/egress versions, durable state, management-port isolation, and the manager's authorization/initialization contract. Same-UID replacement, live binding removal, pause/resume, snapshot/template carry, restore, and owner migration are unsupported; use terminal deletion and a new UID, preserve owner/Vault v2 files, and do not downgrade to v1-only binaries as a rollback shortcut ([#2441](https://github.com/opensandbox-group/OpenSandbox/pull/2441) [#2460](https://github.com/opensandbox-group/OpenSandbox/pull/2460) [#2493](https://github.com/opensandbox-group/OpenSandbox/pull/2493)).
- Experimental subject readiness: with `OPENSANDBOX_EGRESS_EXPERIMENTAL_REVISION_RUNTIME=true`, data-plane-ready can return 503 until current authority and snapshot acknowledgement exist, including after restart or repeated binding SET; unresolved readiness leaves creates Pending/Unavailable after `fastpath_wait_ready_seconds` (default 30 seconds). The flag remains off by default ([#2666](https://github.com/opensandbox-group/OpenSandbox/pull/2666)).
- Experimental Fast Sandbox TLS admission is selected by `OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound`; with the switch unset, both legacy revision-runtime and TLS-admission gates set to true remain a deprecated alias, while revision-runtime alone retains installation-only behavior. Explicit `all` conflicts with either true legacy gate, explicit `credential-bound` conflicts with an explicitly disabled gate, and empty/unknown values or setting this Fast Sandbox-only switch on sidecar fail startup; this mode still breaks decrypted application traffic by design and must not be enabled in production ([#2737](https://github.com/opensandbox-group/OpenSandbox/pull/2737) [#2797](https://github.com/opensandbox-group/OpenSandbox/pull/2797)).
- Credential-bound startup now requires transparent MITM and `dns+nft`, including when using the legacy alias; remove extra interception ports beyond `80,443`, insecure upstream verification, chained proxies, and effective mitmproxy `ignore_hosts` / `allow_hosts`. Runtime-user `config.yaml` then `config.yml` are checked before network setup, and read/parse failures stop startup; remove incompatible settings or return to `all` with both legacy gates unset ([#2797](https://github.com/opensandbox-group/OpenSandbox/pull/2797)).
- Experimental TLS budgets default to 32 connections per subject and 131072 shared, configurable through `OPENSANDBOX_EGRESS_FSB_TLS_CAPACITY` and `OPENSANDBOX_EGRESS_FSB_PROCESS_TLS_CAPACITY`; they are limits, not reserved shares or memory-sizing recommendations. Tokens remain charged until disconnect, opaque connections consume no slot, and the defaults have not been memory-benchmarked ([#2737](https://github.com/opensandbox-group/OpenSandbox/pull/2737)).
- Experimental TLS ports: remove `OPENSANDBOX_EGRESS_MITMPROXY_EXTRA_PORTS` when enabling the sidecar live revision runtime; Fast Sandbox credential-bound mode also rejects nondefault extra ports at startup. The Fast Sandbox handshake experiment denies SNI-bearing non-443 TLS, with existing ECH/no-SNI opaque exceptions retained ([#2587](https://github.com/opensandbox-group/OpenSandbox/pull/2587) [#2737](https://github.com/opensandbox-group/OpenSandbox/pull/2737) [#2797](https://github.com/opensandbox-group/OpenSandbox/pull/2797)).
- Fast Sandbox port policies are now accepted instead of returning 400, but remain TCP-only, with at most 256 ports per rule and no domain-plus-port combinations. Targetless allows do not authorize DNS under default-deny, DELETE target `""` removes all port-only rules, and normal policy updates preserve established flows ([#2662](https://github.com/opensandbox-group/OpenSandbox/pull/2662)).
- Established-flow blocking is available only for PATCH/DELETE on the dns+nft sidecar; POST ignores `dropEstablished`, and dns-only, live-revision, or chained-proxy-plus-transparent-MITM configurations return 501 without applying the change. `droppedEstablished` is a best-effort count; blocks survive later applies until reallowed or aged out, removing a port-only allow alone does not trigger them, and typed SDK support remains follow-up work ([#2346](https://github.com/opensandbox-group/OpenSandbox/pull/2346)).
- Policy validation: replace unsupported `defaultAction` values with `allow` or `deny`; invalid values now return 400 or fail policy-file loading, while missing/empty values still mean deny ([#2693](https://github.com/opensandbox-group/OpenSandbox/pull/2693)).
- Policy PATCH now retains untouched deny rules rather than opening their traffic; send an explicit change to the relevant scope when removing or replacing a rule ([#2664](https://github.com/opensandbox-group/OpenSandbox/pull/2664) [#2662](https://github.com/opensandbox-group/OpenSandbox/pull/2662)).
- Ingress wake configuration must satisfy `--wake-park-budget < --wake-max-flight-lifetime`; defaults are unchanged, and queueing plus waiting now consumes one park budget rather than nearly two ([#2511](https://github.com/opensandbox-group/OpenSandbox/pull/2511) [#2513](https://github.com/opensandbox-group/OpenSandbox/pull/2513)).
- Ingress legacy hostname ports must be canonical decimal values from 1 to 65535; replace zero-padded or out-of-range spellings, which now return 400 ([#2578](https://github.com/opensandbox-group/OpenSandbox/pull/2578)).
- Ingress telemetry now reports final statuses after 1xx responses and correctly extracts client hops without spaces; dashboards or log consumers relying on the previous values will see corrected data ([#2484](https://github.com/opensandbox-group/OpenSandbox/pull/2484) [#2688](https://github.com/opensandbox-group/OpenSandbox/pull/2688)).
- Fast Sandbox ResourceAware direct-Firecracker admission settings move to `resource-admission.json` v3: old Fastlets accept only v2, and new direct-Firecracker Fastlets reject v2 settings. Coordinate controller/Fastlet rollout by pool rather than replacing binaries independently; the admission heartbeat protocol remains v2 ([#2626](https://github.com/opensandbox-group/OpenSandbox/pull/2626) [fast-sandbox#162](https://github.com/opensandbox-group/fast-sandbox/pull/162)).
- ResourceAware direct Firecracker requires writable cgroup-v2 controls, working `clone3(CLONE_INTO_CGROUP)`, and zero effective pool swap. The shared VMM memory ceiling does not create per-VM host-memory caps or protect against node/Pod-wide OOM; aggregate pressure can kill any VMM, and live-VM survival across container replacement is not promised ([#2626](https://github.com/opensandbox-group/OpenSandbox/pull/2626) [fast-sandbox#162](https://github.com/opensandbox-group/fast-sandbox/pull/162)).
- Free-page reporting requires rebuilding object-store templates and a compatible Firecracker binary; missing guest-kernel support warns, while unsupported VMM support fails the build. Existing/restored device state cannot be toggled, so rollback selects an older template; reporting does not justify automatically raising overcommit ratios and is not yet enabled for OCI template builds ([#2546](https://github.com/opensandbox-group/OpenSandbox/pull/2546) [fast-sandbox#114](https://github.com/opensandbox-group/fast-sandbox/pull/114)).
- Strict Actions v2 also requires matching Fastlet `actionsApiVersion: sandbox.fast.io/actions/v2` and egress configuration, clean-base direct-Firecracker deployment, durable retirement fences, and verified management-port isolation. Do not switch protocol versions with existing runtime state or treat owner fencing as authentication; snapshot/pause/restore and same-UID reuse remain unsupported ([#2546](https://github.com/opensandbox-group/OpenSandbox/pull/2546) [fast-sandbox#152](https://github.com/opensandbox-group/fast-sandbox/pull/152)).
- RootfsOnly defaults off, is template-only rather than a pause/checkpoint replacement, and requires qualified patched Firecracker 1.16.1, a live guest-control helper, qualified kernel/OverlayBD backend, and exclusive ext4 ownership. `FAST_SANDBOX_ROOTFS_QUALIFICATION` must identify an absolute qualification profile with matching executable/kernel/backend digests and storage attestation; no application-memory preservation or validated cross-CPU/cross-architecture portability is claimed ([#2706](https://github.com/opensandbox-group/OpenSandbox/pull/2706) [fast-sandbox#173](https://github.com/opensandbox-group/fast-sandbox/pull/173)).
- RootfsOnly recovery uses the new Fastlet Proxy availability endpoint; deploy matching Fastlet/Proxy builds and preserve recovery journals/fences instead of deleting them to force availability ([#2706](https://github.com/opensandbox-group/OpenSandbox/pull/2706) [fast-sandbox#173](https://github.com/opensandbox-group/fast-sandbox/pull/173)).
- OCI deployments now reserve idle ublk devices by default; set `runtime.oci.poolLow=0` for previous on-demand allocation. `poolSizeGB` should match the built rootfs capacity rounded up to GiB; one daemon supports one pooled capacity, while mismatches fall back to cold allocation ([#2594](https://github.com/opensandbox-group/OpenSandbox/pull/2594) [fast-sandbox#163](https://github.com/opensandbox-group/fast-sandbox/pull/163)).
- Fast Sandbox controller cache scope must include all workload/template namespaces and the runtime-environment namespace, with startup explicitly checking the latter. Configure client QPS/burst together; empty scope and zero tuning keep defaults ([#2581](https://github.com/opensandbox-group/OpenSandbox/pull/2581) [fast-sandbox#161](https://github.com/opensandbox-group/fast-sandbox/pull/161)).
- OCI layer compaction can leave longer chains if tools, workspace, fetch, or merge operations are unavailable; at the final pin, failure to clean downloaded squash inputs aborts publication rather than leaking them ([#2546](https://github.com/opensandbox-group/OpenSandbox/pull/2546) [fast-sandbox#158](https://github.com/opensandbox-group/fast-sandbox/pull/158) [#2706](https://github.com/opensandbox-group/OpenSandbox/pull/2706) [fast-sandbox#173](https://github.com/opensandbox-group/fast-sandbox/pull/173)).
- Fast Sandbox init mode remains opt-in in production and requires rebuilding existing templates; execd is a subreaper beneath guest PID 1, not a replacement PID 1 ([#2494](https://github.com/opensandbox-group/OpenSandbox/pull/2494) [#2497](https://github.com/opensandbox-group/OpenSandbox/pull/2497)).
- Chart P2P remains enabled unless disabled; custom `runtime.config` needs separate adjustment when selecting direct-origin delivery. Existing-secret upgrades remove the unused development Secret ([#2566](https://github.com/opensandbox-group/OpenSandbox/pull/2566) [#2695](https://github.com/opensandbox-group/OpenSandbox/pull/2695)).

## Installation

```bash
# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.1            # Python
npm install @alibaba-group/opensandbox@1.2.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.1")
dotnet add package Alibaba.OpenSandbox --version 1.2.1
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.1

# Run the server locally
uvx opensandbox-server==1.2.1
```
