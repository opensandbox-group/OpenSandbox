Stable patch release for users upgrading from `1.2.0`, including both `1.2.1` release candidates and subsequent fixes. Server, CLI, SDKs, charts, and platform images ship together at `1.2.1`.

## Highlights

- **Dynamic credentials:** Credential Vault Exchange resolves credentials per request across the server, egress, and all five SDKs, without vault persistence of resolved secrets ([#2457](https://github.com/opensandbox-group/OpenSandbox/pull/2457) [#2535](https://github.com/opensandbox-group/OpenSandbox/pull/2535) [#2534](https://github.com/opensandbox-group/OpenSandbox/pull/2534) [#2560](https://github.com/opensandbox-group/OpenSandbox/pull/2560)).
- **Multi-version Fast Sandbox VMMs:** managed Firecracker 1.16.1/1.17.0 bundles let new template builds select the highest installed version while existing artifacts restore with their exact recorded VMM version, failing explicitly if it is unavailable ([#2795](https://github.com/opensandbox-group/OpenSandbox/pull/2795) [#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#189](https://github.com/opensandbox-group/fast-sandbox/pull/189)).
- **Safer data and capacity management:** staged uploads reduce overwrite data loss where atomic replacement is available, controller restarts preserve live-sandbox Pods, and Docker enforces requested writable-layer disk quotas ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478) [#2398](https://github.com/opensandbox-group/OpenSandbox/pull/2398) [#2716](https://github.com/opensandbox-group/OpenSandbox/pull/2716)).

## Server

- Carry template CPU/memory shapes through creation and snapshot restore on `ResourceAware` pools; legacy pools retain their existing behavior ([#2602](https://github.com/opensandbox-group/OpenSandbox/pull/2602) [#2619](https://github.com/opensandbox-group/OpenSandbox/pull/2619) [#2623](https://github.com/opensandbox-group/OpenSandbox/pull/2623) [#2628](https://github.com/opensandbox-group/OpenSandbox/pull/2628) [#2633](https://github.com/opensandbox-group/OpenSandbox/pull/2633)).
- Enforce Docker `resourceLimits.disk` on the writable container layer, returning 400 for unsupported drivers or invalid limits instead of silently ignoring them ([#2716](https://github.com/opensandbox-group/OpenSandbox/pull/2716)).
- Allow Docker snapshots directly from paused sandboxes ([#1941](https://github.com/opensandbox-group/OpenSandbox/pull/1941)).
- Move the server-proxied data path into maintenance mode; existing traffic remains supported, but deployments should migrate to the ingress gateway ([#2548](https://github.com/opensandbox-group/OpenSandbox/pull/2548)).
- Reject unknown fields in closed request objects rather than silently accepting misspelled options ([#2576](https://github.com/opensandbox-group/OpenSandbox/pull/2576)).
- Reduce Kubernetes API traffic and list costs through per-object informer invalidation and server-side metadata selectors ([#2599](https://github.com/opensandbox-group/OpenSandbox/pull/2599) [#2559](https://github.com/opensandbox-group/OpenSandbox/pull/2559)).
- Require OCI template artifacts to be SHA-256-pinned in the expected repository ([#2491](https://github.com/opensandbox-group/OpenSandbox/pull/2491)).
- Fail startup when Docker expiration enforcement cannot be restored, except for concurrently removed containers ([#2533](https://github.com/opensandbox-group/OpenSandbox/pull/2533)).
- Other fixes improve create-timeout diagnostics and idle-pause probe bounds ([#2434](https://github.com/opensandbox-group/OpenSandbox/pull/2434) [#2596](https://github.com/opensandbox-group/OpenSandbox/pull/2596)); Docker mount, host-path, and resource validation ([#2421](https://github.com/opensandbox-group/OpenSandbox/pull/2421) [#2505](https://github.com/opensandbox-group/OpenSandbox/pull/2505) [#2474](https://github.com/opensandbox-group/OpenSandbox/pull/2474) [#2701](https://github.com/opensandbox-group/OpenSandbox/pull/2701) [#2751](https://github.com/opensandbox-group/OpenSandbox/pull/2751)); proxy GET bodies and exhaustion errors ([#2518](https://github.com/opensandbox-group/OpenSandbox/pull/2518) [#2519](https://github.com/opensandbox-group/OpenSandbox/pull/2519)); and empty metadata filters, name validation, and API error codes ([#2461](https://github.com/opensandbox-group/OpenSandbox/pull/2461) [#2499](https://github.com/opensandbox-group/OpenSandbox/pull/2499) [#2702](https://github.com/opensandbox-group/OpenSandbox/pull/2702) [#2703](https://github.com/opensandbox-group/OpenSandbox/pull/2703)).

- Enforce Fast Sandbox per-subject TCP port and IP/CIDR-plus-port policies, including original-destination checks through MITM ([#2662](https://github.com/opensandbox-group/OpenSandbox/pull/2662)).
- Hot-reload Fast Sandbox operator deny/allow rules and reachable-port caps without restarting egress; changes apply atomically across active subjects, retaining the previous policy on failure and rejecting stale DNS answers after revocation. The network-security guide documents deployment, precedence, and enforcement boundaries while preserving old guide URLs ([#2727](https://github.com/opensandbox-group/OpenSandbox/pull/2727) [#2814](https://github.com/opensandbox-group/OpenSandbox/pull/2814)).
- Allow dns+nft sidecar policy PATCH/DELETE to opt into blocking established traffic with `dropEstablished=true`; Fast Sandbox is not supported ([#2346](https://github.com/opensandbox-group/OpenSandbox/pull/2346)).
- **[EXPERIMENTAL]** Harden strict Actions v2 ownership/persistence and subject readiness with durable fences, authenticated child sessions, and acknowledged policy/Vault snapshots; defaults remain unchanged ([#2441](https://github.com/opensandbox-group/OpenSandbox/pull/2441) [#2460](https://github.com/opensandbox-group/OpenSandbox/pull/2460) [#2493](https://github.com/opensandbox-group/OpenSandbox/pull/2493) [#2586](https://github.com/opensandbox-group/OpenSandbox/pull/2586) [#2589](https://github.com/opensandbox-group/OpenSandbox/pull/2589) [#2609](https://github.com/opensandbox-group/OpenSandbox/pull/2609) [#2634](https://github.com/opensandbox-group/OpenSandbox/pull/2634) [#2649](https://github.com/opensandbox-group/OpenSandbox/pull/2649) [#2666](https://github.com/opensandbox-group/OpenSandbox/pull/2666) [#2708](https://github.com/opensandbox-group/OpenSandbox/pull/2708)).

## Upgrade & Compatibility

- **Managed Firecracker:** deploy matching charts, runtime, and builder images; `runtimeEnvironments` → `firecracker.firecracker.vmmDir` is now supported and must reference an absolute managed-binary directory. New managed builds choose the highest installed version (currently 1.17.0); Full/RootfsOnly restores require the manifest-recorded version and fail if it is unavailable, rather than falling back to latest. Keep 1.16.1 binaries for existing artifacts without relabeling them; retaining old binaries does not guarantee downgrade compatibility for persisted Fast Sandbox state ([#2795](https://github.com/opensandbox-group/OpenSandbox/pull/2795) [#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#189](https://github.com/opensandbox-group/fast-sandbox/pull/189)).
- **Request validation:** remove unknown keys from closed request objects and use only one alias spelling; these now return 422. Replace `ImageAuth.token`/Docker-config extras with supported `username`/`password`, remove trailing newlines from names/addresses, and use only `allow`/`deny` for policy `defaultAction` ([#2576](https://github.com/opensandbox-group/OpenSandbox/pull/2576) [#2499](https://github.com/opensandbox-group/OpenSandbox/pull/2499) [#2693](https://github.com/opensandbox-group/OpenSandbox/pull/2693)).
- **SDK credential models:** Kotlin/C# are not ABI-compatible with `1.2.0`; recompile and review widened sources and nullable/typeless auth assumptions. Exchange auth contains only `credential`; Python inline sources reject extra keys, and generated-model users should prefer handwritten models. Use keyed Go literals for changed source/metadata models and `Execution`; JSON round-tripping loses `Execution.Text()`'s private formatting mode ([#2560](https://github.com/opensandbox-group/OpenSandbox/pull/2560) [#2534](https://github.com/opensandbox-group/OpenSandbox/pull/2534) [#2447](https://github.com/opensandbox-group/OpenSandbox/pull/2447)).
- **Proxy/ingress:** migrate maintenance-only server-proxy options to ingress; legacy hostname ports must be canonical decimals in `1–65535`, and `--wake-park-budget` must be below `--wake-max-flight-lifetime` ([#2548](https://github.com/opensandbox-group/OpenSandbox/pull/2548) [#2578](https://github.com/opensandbox-group/OpenSandbox/pull/2578) [#2511](https://github.com/opensandbox-group/OpenSandbox/pull/2511)).
- **Docker quotas:** supplied `disk`/`storage`/`ephemeral-storage` limits must be positive and supported by the storage driver or creation returns 400. Only the writable layer is covered, not bind mounts, volumes, or image layers; Windows retains its existing disk-size behavior ([#2716](https://github.com/opensandbox-group/OpenSandbox/pull/2716)).
- **Docker preflight/startup:** correct duplicate, root, colon-containing, or reserved mount destinations and quantities above signed int64; an explicit `/` host-path allowlist authorizes all POSIX descendants. Expiration-restore failures now prevent startup unless the container was concurrently removed; investigate persistent daemon errors ([#2421](https://github.com/opensandbox-group/OpenSandbox/pull/2421) [#2505](https://github.com/opensandbox-group/OpenSandbox/pull/2505) [#2751](https://github.com/opensandbox-group/OpenSandbox/pull/2751) [#2474](https://github.com/opensandbox-group/OpenSandbox/pull/2474) [#2533](https://github.com/opensandbox-group/OpenSandbox/pull/2533)).
- **Downloads:** detailed APIs remain optional for custom adapters; check 206/`isPartial` and ranges before appending, and close response bodies. Unknown totals use `-1`; encoded HTTP lengths/ranges are not decoded progress or resume offsets. Python callers should catch SDK exceptions rather than raw `httpx` errors ([#1597](https://github.com/opensandbox-group/OpenSandbox/pull/1597) [#2592](https://github.com/opensandbox-group/OpenSandbox/pull/2592) [#2515](https://github.com/opensandbox-group/OpenSandbox/pull/2515) [#2525](https://github.com/opensandbox-group/OpenSandbox/pull/2525)).
- **Timeouts and polling:** Python command streams time out after `max(request_timeout, 30s)` without bytes; raise `request_timeout` for legitimate silence. MCP pollers must read logs once more after completion and retain opaque cursors; empty output is not completion. Custom Go pool stores must honor cancellation, and incomplete destruction stays fenced for retry ([#2527](https://github.com/opensandbox-group/OpenSandbox/pull/2527) [#2648](https://github.com/opensandbox-group/OpenSandbox/pull/2648) [#2580](https://github.com/opensandbox-group/OpenSandbox/pull/2580)).
- **Upload atomicity:** use writable containing directories for staged uploads/isolated replacements; existing writable files fall back to non-atomic truncation on staging permission errors. Ordinary `/files/replace` remains in-place. Staged replacement preserves modes, not xattrs/ACLs/capabilities/SELinux labels; ownership is best effort for ordinary writes and session UID/GID for isolated writes ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- **Upload storage:** hardlinks/open readers retain the old inode, multipart overwrites may need roughly three times the file size, and interrupted writers can leave staging files. Avoid reserved `.osb-upload-`/`.osb-staging-` names, especially a prefix plus 16 hex digits; rename existing collisions directly. Special-file targets are rejected, while bind-mounted/open files can prevent rename; directory sync is best effort ([#2433](https://github.com/opensandbox-group/OpenSandbox/pull/2433) [#2478](https://github.com/opensandbox-group/OpenSandbox/pull/2478)).
- **Session lifecycle:** isolated foreground stdin is now `/dev/null`; use files or here-documents. Bash-session deletion terminates all overlapping runs; PTY close adds SIGHUP and up to 500 ms before group kill, while `nohup`/HUP-ignoring jobs can survive ([#2517](https://github.com/opensandbox-group/OpenSandbox/pull/2517) [#2731](https://github.com/opensandbox-group/OpenSandbox/pull/2731) [#2733](https://github.com/opensandbox-group/OpenSandbox/pull/2733)).
- **Jupyter/JVM:** custom images need an explicit token or discoverable runtime token files and the requested kernel. Prefer shaded `sandbox-api` 1.0.18+ over `EXECD_SSE_LEGACY_COMPAT`, which is off by default and removes structured `exit_code` values ([#2448](https://github.com/opensandbox-group/OpenSandbox/pull/2448) [#2689](https://github.com/opensandbox-group/OpenSandbox/pull/2689) [#2472](https://github.com/opensandbox-group/OpenSandbox/pull/2472)).
- **Controller configuration:** cache scope must include all managed namespaces, plus Fast Sandbox template/runtime-environment namespaces; it does not change RBAC or provide tenant isolation. Review `controller.podRecovery.*`, which now takes effect, and remove obsolete ConfigMaps left by plain-manifest upgrades. Custom election timings require lease > renew > 1.2×retry ([#2571](https://github.com/opensandbox-group/OpenSandbox/pull/2571) [#2581](https://github.com/opensandbox-group/OpenSandbox/pull/2581) [fast-sandbox#161](https://github.com/opensandbox-group/fast-sandbox/pull/161) [#2694](https://github.com/opensandbox-group/OpenSandbox/pull/2694) [#2651](https://github.com/opensandbox-group/OpenSandbox/pull/2651)).
- **Exchange deployment:** align server/SDK/egress versions; the sidecar live revision runtime does not support exchange. Resolver caller authentication is not implemented—Ed25519/JWKS remains design-only. Use a protected UDS or trusted-egress-only HTTPS with trusted CAs; sandbox allow rules must not expose resolvers, and MITM UID exclusion alone is not isolation ([#2501](https://github.com/opensandbox-group/OpenSandbox/pull/2501) [#2549](https://github.com/opensandbox-group/OpenSandbox/pull/2549) [#2631](https://github.com/opensandbox-group/OpenSandbox/pull/2631) [#2547](https://github.com/opensandbox-group/OpenSandbox/pull/2547)).
- **[EXPERIMENTAL] Strict Actions v2:** enable matching `OPENSANDBOX_EGRESS_ACTIONS_API_VERSION`/Fastlet `actionsApiVersion` values of `sandbox.fast.io/actions/v2` only on clean-base direct-Firecracker deployments with durable state, isolated management ports, and manager authorization. Pause/resume, snapshots/restore, live binding removal, owner migration, and same-UID reuse remain unsupported; use terminal deletion/new UIDs, preserve fences, and never treat fencing as authentication or downgrade existing state to v1 ([#2441](https://github.com/opensandbox-group/OpenSandbox/pull/2441) [#2460](https://github.com/opensandbox-group/OpenSandbox/pull/2460) [#2493](https://github.com/opensandbox-group/OpenSandbox/pull/2493) [#2546](https://github.com/opensandbox-group/OpenSandbox/pull/2546) [fast-sandbox#152](https://github.com/opensandbox-group/fast-sandbox/pull/152)).
- **[EXPERIMENTAL] Credential-bound interception:** `OPENSANDBOX_EGRESS_FSB_INTERCEPTION_MODE=credential-bound` still denies decrypted application forwarding and must not be enabled in production. With the switch unset, both legacy gates enabled remain a deprecated alias; revision-runtime alone is installation-only. Explicit mode/gate conflicts, empty/unknown values, and setting this switch on sidecar fail startup ([#2737](https://github.com/opensandbox-group/OpenSandbox/pull/2737) [#2797](https://github.com/opensandbox-group/OpenSandbox/pull/2797)).
- **Experimental startup requirements:** credential-bound mode requires transparent MITM, `dns+nft`, and only default interception ports `80,443`; remove insecure TLS verification, chained proxies, and effective `ignore_hosts`/`allow_hosts`. Runtime-user `config.yaml` then `config.yml` are checked; read/parse errors fail closed. To return to `all`, unset both legacy gates; sidecar live revision also rejects extra interception ports ([#2587](https://github.com/opensandbox-group/OpenSandbox/pull/2587) [#2797](https://github.com/opensandbox-group/OpenSandbox/pull/2797)).
- **Port policies:** Fast Sandbox supports TCP only, at most 256 ports per rule, and no domain-plus-port combinations; normal updates preserve established flows. `dropEstablished` is supported only on dns+nft sidecar PATCH/DELETE, ignored by POST, and unsupported in Fast Sandbox, dns-only, live-revision, or chained-proxy-plus-transparent-MITM modes; it installs packet drops, not TCP resets. Removing a port-only allow alone does not trigger established-flow blocking ([#2662](https://github.com/opensandbox-group/OpenSandbox/pull/2662) [#2346](https://github.com/opensandbox-group/OpenSandbox/pull/2346)).
- **Operator-rule reload:** Fast Sandbox reloads runtime-mutable rule files on a one-minute tick; mount ConfigMaps as directories, not `subPath`, and allow for kubelet projection delay. Image-baked rules still require a new image and recreation. Successful reloads clear DNS-learned leases, so allowed domains need another lookup; failed reloads retain the previous overlay, and established connections are not forcibly terminated ([#2727](https://github.com/opensandbox-group/OpenSandbox/pull/2727) [#2814](https://github.com/opensandbox-group/OpenSandbox/pull/2814)).
- **Network-security boundaries:** domain denies filter DNS, not direct connections to known IPs; use explicit IP/CIDR denies or default-deny policies for those paths. Operator denies override operator allows, so permitted internal services require a deny-range carve-out. Classic Docker/Kubernetes creation injects egress only when `networkPolicy` is supplied; `poolRef` plus `networkPolicy` is unsupported, so configure pooled controls in the template ([#2814](https://github.com/opensandbox-group/OpenSandbox/pull/2814)).
- **ResourceAware rollout:** direct-Firecracker `resource-admission.json` moves from v2 to v3; old/new Fastlets reject the other configuration version, so coordinate controller/Fastlet upgrades per pool. Heartbeats remain v2. Hosts require writable cgroup v2, `clone3(CLONE_INTO_CGROUP)`, and zero effective pool swap; the shared memory ceiling is not per-VM protection or a guarantee of survival across container replacement ([#2626](https://github.com/opensandbox-group/OpenSandbox/pull/2626) [fast-sandbox#162](https://github.com/opensandbox-group/fast-sandbox/pull/162)).
- **Restore sizing:** ResourceAware pools use template CPU/memory shapes; new snapshots replay source limits, which restore-time caller limits must match. Legacy pools and snapshots without recorded limits retain their prior behavior ([#2623](https://github.com/opensandbox-group/OpenSandbox/pull/2623) [#2628](https://github.com/opensandbox-group/OpenSandbox/pull/2628) [#2633](https://github.com/opensandbox-group/OpenSandbox/pull/2633)).
- **[EXPERIMENTAL] RootfsOnly:** Full remains the default; explicit RootfsOnly mode is available through Fast Sandbox FastPath/CRDs for reusable OCI snapshots, not pause/resume or OpenSandbox REST/SDK mode selection. New capture requires qualified patched Firecracker 1.17.0 templates, a live guest helper, qualified kernel/OverlayBD backend, exclusive ext4 ownership, and an absolute `FAST_SANDBOX_ROOTFS_QUALIFICATION` profile with matching digests/storage attestation; custom binary digests do not bypass the version gate. Upgrade runtime, Fastlet/Proxy, builder, and tools together, rebuild qualified templates, and preserve journals/fences. Restore cold-boots and reruns the entrypoint; no application-memory preservation or validated cross-CPU/architecture portability is promised ([#2706](https://github.com/opensandbox-group/OpenSandbox/pull/2706) [fast-sandbox#173](https://github.com/opensandbox-group/fast-sandbox/pull/173) [#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#177](https://github.com/opensandbox-group/fast-sandbox/pull/177) [fast-sandbox#189](https://github.com/opensandbox-group/fast-sandbox/pull/189)).
- **OverlayBD template builds:** guest-control injection and freeze/thaw validation are now mandatory for the OCI builder; `FSB_GUEST_CONTROL_ENABLED` is no longer an opt-out. Missing/incompatible helpers or failed probes stop the build. Native templates are unchanged; existing OCI templates need rebuilding rather than metadata edits to gain capture capability ([#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#183](https://github.com/opensandbox-group/fast-sandbox/pull/183)).
- **Fast Sandbox logs:** covered Kubernetes components now write rotating files under `/var/log/fast-sandbox` by default (100 MiB per file, 10 backups, 7-day backup retention, gzip); application logs no longer appear in `kubectl logs` unless `alsoStderr: true` is configured. Replace legacy klog output flags with the shared logging YAML, wire ConfigMap/log-volume mounts for chart-managed static workloads, and configure each tenant namespace separately. Configuration is startup-only: use controlled Pool draining/replacement for Fastlets, not deletion of live Pods, and arrange collection before ephemeral logs are lost. Explicit missing/invalid configuration or unwritable output prevents startup; rotation limits are not a hard disk quota and do not cover guest/VM logs ([#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#197](https://github.com/opensandbox-group/fast-sandbox/pull/197)).
- **OCI checkpoint cache:** reserve space for the additional blob cache (defaults: 16 GiB, 4096 files, 1 GiB free-space reserve), separately from OverlayBD's block cache. Keep staging/cache/device state on one filesystem for hard-link reuse; cross-filesystem placement or contention falls back to the registry. Set `FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES=0` to disable blob-cache insertion/lookups; active-device pins remain protected, including when budgets shrink ([#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#178](https://github.com/opensandbox-group/fast-sandbox/pull/178)).
- **ublkd recovery:** automatic shared-snapfiles rebuilding applies only when no other Sandbox lease needs the attachment; it is not transparent recovery of running VMs. Remove affected Sandboxes through their normal lifecycle before retrying when other leases remain, rather than manually wiping shared caches ([#2812](https://github.com/opensandbox-group/OpenSandbox/pull/2812) [fast-sandbox#193](https://github.com/opensandbox-group/fast-sandbox/pull/193)).
- **Template rebuilds:** opt-in `runtime.execd_run_as_init` needs rebuilt templates; execd remains a subreaper beneath guest PID 1. Free-page reporting also needs rebuilt object-store templates and compatible VMM/kernel support, cannot toggle restored device state, and does not enable OCI reporting or justify higher overcommit; rollback uses an older template ([#2494](https://github.com/opensandbox-group/OpenSandbox/pull/2494) [#2497](https://github.com/opensandbox-group/OpenSandbox/pull/2497) [#2546](https://github.com/opensandbox-group/OpenSandbox/pull/2546) [fast-sandbox#114](https://github.com/opensandbox-group/fast-sandbox/pull/114)).
- **OCI chart defaults:** idle ublk devices are now reserved; set `runtime.oci.poolLow=0` for on-demand allocation and match `poolSizeGB` to rounded-up rootfs capacity. P2P remains enabled by default; custom `runtime.config` needs separate adjustment for direct-origin delivery ([#2594](https://github.com/opensandbox-group/OpenSandbox/pull/2594) [fast-sandbox#163](https://github.com/opensandbox-group/fast-sandbox/pull/163) [#2566](https://github.com/opensandbox-group/OpenSandbox/pull/2566)).
- **Snapshot integrity:** missing commit digests now fail pause while retaining Pods; old snapshots are not repaired. OCI template references must carry a full SHA-256 digest in the expected repository; rebuild invalid references ([#2482](https://github.com/opensandbox-group/OpenSandbox/pull/2482) [#2491](https://github.com/opensandbox-group/OpenSandbox/pull/2491)).
- **CLI scripts:** non-positive request timeouts and empty rule targets are usage errors; `osb config init` overwrite refusal now exits 1 without changing the file ([#2742](https://github.com/opensandbox-group/OpenSandbox/pull/2742) [#2692](https://github.com/opensandbox-group/OpenSandbox/pull/2692) [#2743](https://github.com/opensandbox-group/OpenSandbox/pull/2743)).
- **VM console collection:** opt in to `vm-console`, align `hostPaths.vmConsole` with the runtime state root, cover every runtime node, and manage file-sink retention ([#2234](https://github.com/opensandbox-group/OpenSandbox/pull/2234) [#2677](https://github.com/opensandbox-group/OpenSandbox/pull/2677)).
- **Artifact verification:** umbrella workflows do not provide blanket signing/provenance coverage; BOM digest matching is not proof of origin, and signature requirements must not be bypassed ([#2467](https://github.com/opensandbox-group/OpenSandbox/pull/2467)).

```bash
# Platform (Kubernetes) — render the chart at this tag and apply
git clone https://github.com/opensandbox-group/OpenSandbox
cd OpenSandbox
git checkout release-1.2.1
helm dependency build manifests/charts/opensandbox  # package file:// sub-charts (not committed)
helm template ./manifests/charts/opensandbox | kubectl apply -f -
# or point your GitOps platform (Argo / Flux) at the repo path + tag

# SDKs
pip install opensandbox==1.2.1            # Python
npm install @alibaba-group/opensandbox@1.2.1   # JavaScript
# Kotlin/JVM: implementation("com.alibaba.opensandbox:sandbox:1.2.1")
dotnet add package Alibaba.OpenSandbox --version 1.2.1
go get github.com/alibaba/OpenSandbox/sdks/sandbox/go@v1.2.1

# Run the server locally
uvx opensandbox-server==1.2.1
```
