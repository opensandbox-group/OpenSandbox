# OpenSandbox `release-1.3.0-rc.3` ACK OverlayBD Benchmark Report

This report archives the full six-suite `release-1.3.0-rc.3` (`opensandbox` commit `ad653af12d21fedb3871fbf0b07ad2dcefb0a565`, `fast-sandbox` commit `5b96ba7f71e019bcce1c00fc24ddeb2b7a32ce74`, harness commit `f241dfe4e`, chart renderer `cef9ae3bc`) ACK OverlayBD baseline executed on 2026-11-27. Companion artifacts in this directory: [`report.json`](./report.json) (standard `schema_version: 2`, verified with `opensandbox-bench compare` across all 6 suites) and [`plot.html`](./plot.html) (self-contained, zero-CDN interactive visualization generated by `opensandbox-bench plot`). Note: `report.json` consolidates three sequential pool topologies (`2×120`, `2×240`, `1×240`) into one archive and does not include OTel `traces/`; `compare --fail-on-regression` exits non-zero on this baseline because `leak_audit.passed` is `false` (`orphaned_ublk_devices = 1`) and requires the schema-v2 extensions in PR #3176.

## Methodology & Caveats Card

- **Warm-path & pre-warming configuration**: Fastlets pre-initialize `cleanSlots` up to `maxSandboxesPerPod` (`120` per Fastlet in Bundle 1; `240` per Fastlet in Bundle 2; `240` on a single Fastlet in Bundle 3); `overlaybd-ublkd` maintains an OverlayBD `ublk` warm pool on each node with a `16 GiB` (`17179869184` bytes) local OCI blob cache (`FAST_SANDBOX_OCI_BLOB_CACHE_SIZE_BYTES`) and `/dev/shm/fsb-spill` snapshot spill directory; `schedule-burst` runs warmups before timed measurements.
- **Readiness polling interval**: `readiness_poll_ms = 10` (vs SDK default `200 ms`) to keep polling quantization below 10 ms while measuring `t_first_ping`. Primary latency tables focus on `t_api_ack` and `t_first_ping` (`/ping` traverses `ingress -> fastlet-proxy -> execd` end-to-end).
- **Registry boundary**: Template OCI layers are pulled over ACR VPC HTTPS rather than an in-cluster unauthenticated `registry:2` so storage caching and network paths reflect realistic managed-cluster deployment.
- **Minimal image substitution exception**: Nine of ten deployed components ran unmodified `release-1.3.0-rc.3` images; `fsb-fastlet` ran `586ca2d62d7ffae0c806433b695f0f9b6b23fc70` (`sha256:a5852cff57c545e0ed66e2b872c3914fd6a8035ae12d753896a3f87882647892`) solely for Alibaba Cloud Linux Lifsea (ContainerOS) 3 PSI compatibility.
- **Deterministic host & component telemetry**: Dedicated `opensandbox-bench-runner` ServiceAccount bound to `ClusterRole` `opensandbox-bench-runner-reader` passed Telemetry Preflight with **0 RBAC 403 warnings**, real host `active_ublk_devices` (probed via `janitor` `/dev`), real host `conntrack_usage_ratio` (via `nsenter -t 1 -n`), native `StageAttribution`, and structured `ErrorsByOperation`.

## Scope & Known Limitations

- **Covered in this archive**: All 6 OverlayBD suites (`schedule-burst`, `steady-churn`, `high-density-soak`, single-Fastlet `density-ramp`, guest-absolute `dataplane-microbench`, and 100% same-node `noisy-neighbor`), native `StageAttribution`, structured `ErrorsByOperation`, deterministic host `ublk`/`conntrack` telemetry, native three-perspective per-sandbox memory overhead, and fine-grained `LeakAudit.Checks`.
- **Known limitations**: (1) `dataplane-microbench` network probing against cluster Pod IP `10.79.209.76:8080` was blocked by default guest egress/network isolation policy (20/20 failed) and requires an explicitly permitted target endpoint to benchmark proxied network throughput; (2) `dataplane-microbench` ran without a paired bare-metal control run, so only guest-absolute figures are reported; (3) `pause-resume` (Full checkpoint / 24-layer squash), `rootfs-only-restore`, and `wake-storm` (OSEP-0024) were not part of this `rc.3` 6-suite run; (4) Bundle 1 triggered `fast-sandbox#289` (`cleanSlots` leak under high churn), which is tracked separately.
